Overlays get live data from Mycelian over a Socket.IO connection to the built-in web server. This page lists the connection details and the main events, for people writing or editing template JavaScript.

{{icon:dns}} http://127.0.0.1:5000 {{icon:code}} Socket.IO 4 client

Building in Spore Studio? Its event bindings subscribe to these same events without code.

How it fits together

Connecting

The server speaks the Socket.IO protocol on the same address and port as the overlay page (default port 5000, path /socket.io/). A plain new WebSocket('ws://…') will not work; use the Socket.IO client.

All built-in templates load the Socket.IO client and Mycelian's helper, then connect through MycelianOverlay.connect. It adds reconnect settings, announces the overlay to Mycelian, and calls onRecovery when Mycelian asks overlays to resync (for example after a service reconnects).

<script src="https://cdnjs.cloudflare.com/ajax/libs/socket.io/4.0.1/socket.io.js"></script>
<script src="/assets/default_assets/overlay_recovery.js"></script>
<script>
    var socket = MycelianOverlay.connect(
        'http://' + document.domain + ':' + location.port,
        { onRecovery: function () { /* re-request your data */ } }
    );
</script>

const socket = io('http://127.0.0.1:5000', {
    transports: ['websocket', 'polling'],
    reconnection: true
});

socket.on('connect', () => {
    console.log('Connected to Mycelian');
});

The alert object

next_alert, instant_alert and activity_feed_alert carry the alert's fields. Only the fields that matter for the alert type are filled in; the rest keep empty defaults. Common ones:

{
    "alert_type": "sub",          // follow, sub, resub, giftsub, bit, raid, point, donation, ...
    "alert_name": "...",
    "username": "ViewerName",
    "message": "Great stream!",
    "tier": 1,
    "resub_month": 6,
    "gift_qty": 0,
    "recipient": "",
    "amt_cheered": 0,
    "raider_count": 0,
    "point_cost": 0,
    "title": null,                // channel point reward name
    "donation_amount": 0.0,
    "currency": "USD",
    "duration": 5.0,
    "is_test": false,
    "timestamp": 1761150000.0,
    "queue_seq": 42               // next_alert only: echo this in alert_complete
}

Examples

React to alerts

socket.on('next_alert', (alert) => {
    if (alert.alert_type === 'sub') {
        showBanner(alert.username + ' subscribed!');
    }
});

Respond to a Source Controls button

A control with action refresh on template mywidget arrives as mywidget_refresh:

socket.on('mywidget_refresh', (data) => {
    reloadEverything();
});

socket.on('mywidget_toggle_glow', (data) => {
    document.body.classList.toggle('glow', data.enabled);
});

Reload settings after Save

socket.on('template_config_updated', async (data) => {
    if (data.template !== 'mywidget') return;
    const res = await fetch('/api/template-config/mywidget');
    applySettings(await res.json());
});

Read the current category

socket.on('connect', () => socket.emit('get-streamer-info'));

socket.on('streamer-info', (info) => {
    if (info && info.current_category) {
        setCategory(info.current_category);
    }
});

socket.on('twitch_data_update', (data) => {
    if (data.current_category !== undefined) {
        setCategory(data.current_category);
    }
});

Handle reconnects

socket.on('disconnect', (reason) => {
    console.log('Disconnected, will auto-reconnect:', reason);
});

socket.on('connect', () => {
    // Runs on the first connect and after every reconnect.
    requestCurrentState();
});

Debugging

Open the overlay URL in a desktop browser and press F12 (or right-click → Inspect).

  • Console: built-in templates log connection and event messages here.
  • Network: filter by WS, click the socket.io connection, and open Messages to see every event in both directions.
  • The Source Settings preview's mock buttons send sample events, so you can test without real alerts. See Configuring Template Settings.

Troubleshooting

The overlay cannot connect
  • Check Mycelian is running and the overlay server is up in the status footer.
  • Use http://, not https://.
  • Something else may be using port 5000, or a firewall is blocking it. See Connection Problems.
Connected, but my handler never runs
  • Check the event name exactly; names mix underscores and hyphens (next_alert, get-streamer-info).
  • For control events, the prefix is the template's file name: boo chat gives boo chat_trigger.
  • Look for JavaScript errors in the console that stop the script before socket.on runs.
set_data does nothing

set_data, update_data and the Source Controls relay are only accepted from this computer. An overlay opened from another PC can read but not write.

Updates feel delayed

A short delay is normal. If it grows, check CPU use and keep handlers light; see Performance Optimization.
