Mycelian has three ways to try an alert without waiting for a real viewer: Test Alert on the Alerts tab, Replay in the Activity Feed, and the Sample events buttons in the Source Settings preview. Each one checks something different.

Test before you go live. Tests play on the real alerts browser source, so viewers see them if you are streaming.

Test Alert

Open the alert

Go to the Alerts tab, pick the sub-tab, and click the alert in the alert list on the left. You can also test a new alert before saving it.

Click Test Alert

The button is in the header row, next to the alert name and its trigger. A pop-up says Test alert sent (Bits) (or the tab you are on), and the alert joins the queue. If alerts are paused, a warning says Alerts are paused instead, and the test plays when you resume.

Watch the browser source

The alert appears in OBS (or wherever the alerts source is open) with the username TestUser:

Adjust and repeat

Change the volume, file or duration and test again. Click Save when you are happy.

What the test sends:

  • The amount is the trigger amount, or the lowest amount when the switch is on Range. A 100-999 range tests as 100 bits.
  • Subscriptions and Gift Subs test as Tier 1. A one-sub gift shows the recipient TestRecipient.
  • Channel Points test as Test Point Redemption for 1000 points.
  • Test alerts do not appear in the Activity Feed and are not stored.
  • Test Alert does not check range matching. It always plays the alert you have open. Use Replay for that.
  • Tests are always stackable, so they do not wait behind other test alerts.

Replay from the Activity Feed

Every real event is listed on the Activity Feed tab. Hover a row to show its buttons.

  1. Replay Alert (replay) and Skip Alert (skip_next).

Replay Alert takes the stored event (user, amount, message) and matches it against your current saved alerts. If you just changed a range, replaying a 500-bit cheer shows which alert 500 bits now picks. If no saved alert matches, it uses the media stored with the event. A toast says Replaying Bits alert.

No events yet? Have a friend follow, or cheer 1 bit yourself, then replay that row while you tune your alerts.

Preview the template

To check how alerts look rather than which one plays, open Source Settings and select the alerts template. Under the preview, Sample events has Queue alert, Play alert and Refresh. These play a sample in the preview only; OBS does not show them.

Checklist

Tick these off for each alert type you use. Progress is saved.

Basics

  • The image appears and animates.
  • The sound plays at a comfortable level next to your game and voice.
  • The alert stays up long enough to read, then leaves.
  • TTS (if on) reads the right text.

Ranges

  • Each range's Min and Max were checked with Replay or a real event.
  • An amount between two ranges (for example 99 and 100) picks the alert you expect.
  • No two ranges overlap.

Randomizer

  • Several tests in a row play different sounds.
  • The rare sound turns up at least once (raise its chance to 100 to check, then set it back).
  • Random files are about as loud as the primary sound.

Under load

  • Five quick tests in a row play cleanly, one after another.
  • PAUSE ALERTS holds the queue and RESUME ALERTS releases it.
  • SKIP ALERT ends the alert on screen.
  • OBS stays smooth while large GIFs play.

If the test fails

Nothing appears

Check the alerts browser source URL in OBS (http://127.0.0.1:5000/alerts), that the source is visible, and that Overlay Server in the status footer is green. Also check the Activity Feed is not showing RESUME ALERTS, which means alerts are paused. More in Troubleshooting Alerts.

The image shows but there is no sound

Check MUTE ALERTS is not on, the alert's Volume is above 0, and the browser source is not muted in the OBS mixer. See Audio Troubleshooting.

The wrong alert plays for a real event

Test Alert always plays the open alert, so it cannot show this. Replay the event from the Activity Feed, then look for overlapping ranges or a missing range. See Configuring Alert Settings.

A watch-streak test plays but real streaks do not

Enable Watch Streak Alerts in Source Settingsalerts is off by default. Turn it on.
