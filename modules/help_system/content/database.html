Mycelian keeps your settings, alerts and history in one database. By default that is a local file on this computer, and you never need to touch it. The Database tab shows whether it is connected, lets you switch to Firebase or MongoDB, move your data between them, and open the Database Explorer.

The Database tab

The left column is about the connection: the database in use, where to store data, and connection settings. The right column holds the tools for your data. Click the three storage cards in the mock to see the fields each type needs.

  1. The header pill names the database in use: Connected · Local file, Can't connect · Firebase, or Checking · … while the first check runs.
  2. The Connection card always describes the database Mycelian is using now, not the one selected below. The refresh icon (Check now) checks the connection again; Test tries a full connection and reports the result as a notification. The cells below show the type, location (the file name and folder, the Firebase host, or the MongoDB database name) and, for a local file, its size. While the tab is open the status is checked every few seconds.
  3. Pick where to store data. The In use tag marks the database in use; only the selected type's fields are shown. The folder button (folder_open) next to Database file and Service account key file opens a file picker that can browse anywhere on this computer.
  4. Open starts the Database Explorer.
  5. Migrate… opens Move my data.

Connection settings apply to all types: Timeout (5 to 300 seconds, default 30) and Retry attempts (1 to 10, default 3).

Save, test and switch

  • Changes on this tab take effect when you click Save. An Unsaved changes tag shows until then; Discard puts the saved values back.
  • Save checks the new connection first. If it works you see "Database settings saved". If you changed the connection details of the database already in use, the notice adds "Restart Mycelian to use the new connection details."
  • If the new database can't be reached, nothing is switched: you see "Couldn't connect to the … database" with "Mycelian kept using the local database. Your edits are still in the form." Fix the fields, click Test, then Save again.
  • Test shows "Testing the … database connection", then "Connected to the … database" or "Couldn't connect to the … database" with the reason under details. Test checks the database in use, so save first if you just changed the fields.

Switching to another type does not copy anything. Mycelian starts reading the other database, which may be empty. To take your settings, alerts and history with you, use Move my data instead.

Move your data to another database

Move my data copies every stored item from one database to another, then switches Mycelian to the target. The source is left as it was, so it doubles as a backup.

Fill in the target's details

Click the target's card under Storage (for example Firebase) and fill in its fields. Move my data uses the connection details on this tab, so you do not have to save first.

Open Move my data

Click Migrate… under Your data. From starts on the database in use (marked (in use)); choose the target under To.

Start moving and wait

Click Start moving. A progress notice says "Copying your data to the … database" and "Don't close Mycelian until this finishes." Large databases can take several minutes. When it is done you see "Moved your data to the … database", "Mycelian now uses it.", and the tab shows the new database as In use.

If anything fails, Mycelian stays on the database it was using. See Troubleshooting for each message.

Database Explorer

The explorer shows the raw items Mycelian has stored, as a folder tree of paths, and lets you edit any item as JSON. It is meant for advanced fixes; the other tabs are the normal way to change settings.

Edits and deletes are written to the database straight away and can't be undone. A wrong value can break the feature that uses it. Copy the JSON somewhere safe before you change it.

  1. The pill names the database you are looking at (red if it couldn't be read). Refresh reloads everything from the database; New item creates a path.
  2. Type in Search paths to show only matching paths. Click a chevron to open or close a folder; the number is how many items it holds. Click an item to open it. Very large folders show the first 300 rows with a Show … more row.
  3. The breadcrumb shows where you are. Click Root or a folder in it to go back up.
  4. The item's name, full path (the copy button copies it) and chips for its type and size.
  5. Delete asks first: "Delete “ff7_enabled”?", then removes the item and everything in it. This can't be undone.
  6. The editor checks your JSON as you type: Valid JSON, or Invalid JSON: with the problem and line number, for example Invalid JSON: Expecting ',' delimiter (line 3). Format tidies the indentation; Undo changes goes back to the stored value.
  7. Unsaved changes shows while the editor differs from the stored value. Save item (or Ctrl+S, Cmd+S on macOS) writes it. Save only works when the JSON is valid and something changed.

Create or delete an item

Click New item, type a Path such as Settings/MyData and a Starting value (JSON) (it starts as {}), then Create. A leading slash is removed. You see "Created …" and the new item opens.

To delete, open the item and click the red Delete, then Delete again in the confirmation. You see "Deleted …".

Troubleshooting

"Can't connect to the … database"

Mycelian lost its database. The notice says "Changes won't be saved until the connection is back." and the header pill shows Can't connect. Open SettingsDatabase (the notice has a button for it), check the fields of the type in use, and click Test. For Firebase and MongoDB, check your internet connection too. When it comes back you see "Reconnected to the … database".

"Firebase isn't set up correctly" or "service account key file wasn't found"

While Firebase is in use and not connected, a warning under the Firebase fields and a notification list what is wrong:

MessageFix
Service account key not found: … (on Test: The service account key file wasn't found at …)The key file moved or the path is wrong. Click the folder button next to Service account key file and pick the .json key again
Service account path not configuredFill in Service account key file
Database URL not configured, Invalid database URL formatCopy the Realtime Database URL from the Firebase console (it starts with https://)
Firebase SDK not availableThis Mycelian install can't load Firebase. Use a local file or MongoDB

Then click Save, then Test.

"Couldn't connect to the … database" after Save

The new connection failed, so nothing was switched: "Mycelian kept using the … database. Your edits are still in the form." The details show the reason. Correct the fields and save again, or click Discard to put the saved values back.

"Some data couldn't be copied"

The move partly failed: "Copied N of M items. K couldn't be written to the … database, so Mycelian stayed on the … database." Nothing was switched and the source is unchanged. The notice's details list the paths that were Not copied. Check the target's connection and run Move my data again; items already copied are simply overwritten.

"Couldn't read the database" in the explorer

The explorer stays empty until it can read the database. Fix the connection on the Database tab, then click Refresh in the explorer.

"Couldn't save to the … database" or "responding slowly"

A save did not reach the database ("Recent changes may not have been kept."), or took too long. For Firebase and MongoDB, check your internet connection. If it keeps happening, raise Timeout under Connection settings, click Save, and click Test.

"That isn't valid JSON"

Shown when you try to save, format or create an item whose JSON can't be read. The message gives the line and column. Common causes: a missing comma, a trailing comma, or single quotes instead of double quotes.

Where things are stored

  • The database connection (type, file path, Firebase and MongoDB details, timeout, retries) is saved in config.json.
  • The local database is mycelian.db in Mycelian's data folder, unless you chose another file. The Connection card shows its name, folder and size.
  • To back up a local file, close Mycelian and copy the file. With Firebase or MongoDB the data already lives online.
