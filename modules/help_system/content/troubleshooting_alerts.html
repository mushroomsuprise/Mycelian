Find your symptom below. Each one lists the likely causes in the order worth checking, with the fix for each. Most alert problems come down to one of three things: the browser source, the connection, or the alert's settings.

First, two quick checks

  1. Overlay Server serves every browser source. If it is not Running, no alert can show. See Status Footer.
  2. Twitch (or the donation service) must be green to receive events. See Connection Problems.
  3. If the Activity Feed shows Alerts paused and a Resume button, alerts are paused. Click Resume; waiting alerts play in order. See Activity Feed.

Find your symptom

Start by clicking Test Alert on the alert. If the test shows, the overlay works and the problem is the event. If the test does not show either, the problem is the overlay.

Test does not show: wrong or missing browser source

Cause: OBS is not loading the alerts page.

Fix: In OBS, open the browser source's properties and check the URL is http://127.0.0.1:5000/alerts. Make sure the source's eye icon is on and it is in the scene you are viewing. Click Refresh cache of current page in its properties. The exact URLs for every overlay are listed in SettingsAbout under Browser source URLs. See OBS Setup.

Test does not show: Overlay Server is not Running

Cause: The local server on port 5000 did not start, often because another program holds the port. Mycelian then shows an error pop-up, "Another app is using port 5000".

Fix: Close the other program. On macOS, turn off AirPlay Receiver in System SettingsGeneralAirDrop & Handoff. Mycelian retries on its own.

Test does not show: alerts are paused

Cause: Pause was clicked (on the Activity Feed, its dock, a Stream Deck key or a control). The queue holds every alert until you resume; the feed shows an amber Alerts paused banner listing them.

Fix: On the Activity Feed, click Resume. Held alerts then play in order.

Test shows, real events do not: the event never arrives

Cause: Twitch (or Streamlabs, StreamElements, YouTube) is not connected. If the event is missing from the Activity Feed, Mycelian never received it.

Fix: Check the service in the status footer and in SettingsTwitch. See Connection Problems.

Test shows, real events do not: that alert type is switched off

Cause: The event is in the Activity Feed but nothing plays. The type is turned off somewhere.

Fix: Check, in order:

  • SettingsTwitch: Process Twitch alerts is on.
  • Source Settingsalerts: the matching Enable … Alerts box is on. Enable Watch Streak Alerts is off by default.
  • Channel Points: the reward has Use as alert on and was saved. The list shows Not an alert when it is off.
  • The alert sub-tab has at least one saved alert. The count on the sub-tab shows how many.
Alerts are muted

Cause: Mute on the Activity Feed silences sound and text-to-speech; the image still shows. The button then reads Unmute.

Fix: Click Unmute.

The browser source is muted or not routed in OBS

Cause: OBS handles browser-source audio itself.

Fix: In the browser source properties, turn on Control audio via OBS, then check the source's slider and mute button in the Audio Mixer.

No sound file, or volume at 0

Cause: The sound card in Sound says No sound, the file was moved, or Volume is 0%.

Fix: In the alert's Sound section, click Browse on the file card and pick the file again. Supported formats are MP3, WAV, OGG, M4A and FLAC. See Audio Troubleshooting for more.

Ranges overlap or leave gaps

Cause: An exact amount wins first, then the first range that contains the amount. Overlapping ranges make the choice unpredictable; gaps fall back to another alert of the same type.

Fix: Read the alert list on the left of the sub-tab; it is sorted by amount, and range alerts are tagged RANGE, so overlaps and gaps are easy to spot. Make ranges meet end to end (1-99, 100-999, …).

Resubs play the wrong sub alert

Cause: No alert exists for that month and the Resub fallback switch is off.

Fix: On Subscriptions, turn on Resub fallback at the bottom of the alert list and set up the Resub Fallback alert, or add a month range.

Donations pick an unexpected tier

Cause: Tips are converted to the Alert currency and rounded to a whole number before matching. A 4.60 tip matches 5.

Fix: Check Alert currency in SettingsStreamlabs or SettingsStreamElements, and set your ranges in that currency.

To confirm a fix, click the event in the Activity Feed to replay it; replay matches against your current saved alerts. See Activity Feed.

The image is missing

Cause: The file is outside the assets folder, was renamed, or the card in Visual says No GIF or image.

Fix: Move the file under assets/alerts/ and pick it again with Browse on the file card. To check the file is served, open http://127.0.0.1:5000 plus the folder and file name (shown on the card) in a normal browser, for example http://127.0.0.1:5000/assets/alerts/bits/medium_cheer.gif.

The GIF does not animate

Cause: The file is a still image renamed to .gif, or it is so large OBS stutters.

Fix: Open the file in a browser to confirm it moves. Shrink large GIFs (fewer frames and colors, 300-500 px) or convert them to animated WebP.

The image is the wrong size or position

Cause: Size and placement are template settings, not alert settings.

Fix: In Source Settingsalerts, change GIF Width, GIF Height, GIF Top Position, GIF Left Position or GIF Fit Mode. See Template Configuration.

Alerts wait a long time before playing

Cause: Alerts play one at a time. Each waits for the previous alert's duration, its sound and its speech to finish, plus Delay Between Alerts (0.5 seconds by default). A long sound file holds the queue for its full length.

Fix: Shorten Duration and trim long sound files. Turn on Stackable for types that may overlap. Lower Delay Between Alerts in Source Settingsalerts.

One alert is stuck on screen

Cause: The overlay never reported the alert finished, for example after OBS reloaded the source mid-alert.

Fix: Click Skip on the Activity Feed (in the header or on the playing row). It stops the alert at once and starts the next one. If it happens again, refresh the browser source in OBS.

Alerts arrive several seconds after the event

Cause: Network delay between Twitch and this computer, or a busy queue.

Fix: Check the Internet item in the status footer and the queue causes above. If Overlay Server shows Overloaded, see Performance Issues.

I want to empty the queue

The Activity Feed has no clear-queue button. Skip ends the current one, one alert per click. A Spore Studio or Stream Deck control can use the Clear alert queue action; see Dynamic Controls. Restarting Mycelian also empties it.

Read the log

Errors go to mycelian.log in the logs folder next to the Mycelian program. Mycelian also shows the important ones for you:

The log records warnings and errors, not every alert. Useful lines to search for: Audio folder not found (a random-sound folder outside assets/alerts/) and Error in alert queue processor (shown in the app as Alert queue hit an error and may be stalled. Check logs.). To see what the overlay itself is doing, open http://127.0.0.1:5000/alerts in a normal browser, open its developer console, and click Test Alert.
