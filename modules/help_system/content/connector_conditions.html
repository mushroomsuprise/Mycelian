Conditions decide whether a connector's actions run. When the trigger fires, Mycelian checks each condition against the event. If all of them pass, the actions run. If any fails, nothing happens.

Conditions are optional. A connector with none runs on every event of its trigger type.

Adding a condition

  1. Field: which part of the event to check. The choices depend on the trigger (see Connector Triggers).
  2. Operator: shown as a symbol. Hover it in the app to see its name. New conditions start with =.
  3. Value: what to compare against. Type plain text or a number.
  4. Is Moderator is a true/false field. It only offers = and ≠, and Value becomes a True/False list.

On the connector card, these show as chips: Message ^ !scene and Is Moderator = True.

Text matching is case-sensitive. Message ^ !lurk does not match !Lurk. Add a second connector for other spellings if you need them.

First word vs Begins with

For the message !sound airhorn:

  • Message ^ !sound passes. The first word is exactly !sound.
  • Message ^ !so fails. The first word is !sound, not !so.
  • Message ^… !so passes. The text begins with !so.

Use First word for chat commands so !so does not also fire on !sound.

Combining conditions

All conditions on a connector must pass (AND). There is no OR.

AND: one connector, two conditions.

OR: make one connector per case. Duplicate the first ({{icon:more_horiz}} → Duplicate) and change its condition.

Using the rest of the message

When a condition on Message uses Contains, First word, Begins with or Ends with, Mycelian removes the matched text and keeps the rest in {message_after_conditions}. This turns a chat trigger into a command with arguments.

What conditions cannot do

Conditions only compare fields that the event carries. These are not available:

  • Subscriber or VIP checks. Chat events only carry Is Moderator (true for mods and the broadcaster).
  • Time of day, day of week, or stream uptime.
  • A cooldown between runs.
  • "First time" checks such as a viewer's first message. For that, see Chatbot Greetings.
  • "Does not contain" and regular-expression matching. The Operator list does not offer them.

Troubleshooting

The condition never passes
  • Check capitals. Text matching is case-sensitive.
  • Check the value Twitch sends. Sub tiers are 1000, 2000, 3000, not 1, 2, 3.
  • Number operators (≥ ≤ > <) fail when either side is not a number, such as $5. Use Amount, not Display Amount.
  • The field must exist in the event. On Twitch Gift Sub, Gifter Username and Quantity are not sent, so they never match.
  • With First word, the value must be the whole first word. Use Begins with to match part of it.
Test says "did not trigger" but real events work

The Test button uses fixed sample data, for example 100 bits or the chat message Hello test!. If your conditions exclude those values, the test reports Connector did not trigger (conditions not met). See Connector System Introduction for the full list of sample values.

The connector fires too often

Add a narrower condition, for example a minimum Amount, or First word instead of Contains on chat. On Any (all events), always add at least one condition.
