Conditions decide whether a connector's actions run. When the trigger fires, Mycelian checks the conditions against the event. If they match, the actions run; if not, nothing happens.

Conditions are optional. A connector with none runs on every event of its trigger type. You set them in the editor's second step, If · Conditions.

Adding conditions

  1. The first row starts with where. Every other row has an AND/OR pill; click it to switch. An OR row starts a new group, marked by the or line above it. See AND and OR below.
  2. Field: which detail of the event to check. The choices depend on the trigger (see Connector Triggers). Changing the field resets Is and Value.
  3. Is: how to compare. The list depends on whether the field is a number, text or true/false (see the table below).
  4. Value: what to compare against. True/false fields offer a true/false list instead. On text fields, Aa means ignore upper/lower case; it is highlighted when on.
  5. The summary spells out the rule in plain English, so you can check it reads the way you mean. {{icon:close}} at the end of a row removes it.

Click Add condition for a new row. It starts with the trigger's first field, the first choice in Is, and Aa on. Before you pick a trigger the step says Conditions depend on the trigger. Triggers with nothing to check (hotkeys, Stream Deck buttons, timers, set times, Stream ended) say This trigger has nothing to check, so it always runs.

On the connector card, conditions show as short chips, such as Message first word !hype or Bits ≥ 500.

If the event doesn't carry the field at all (possible with Any event or a webhook), the condition fails, except is not and does not contain, which pass.

"first word is" vs "starts with"

For the message !sound airhorn:

  • Message first word is !sound passes. The first word is exactly !sound.
  • Message first word is !so fails. The first word is !sound, not !so.
  • Message starts with !so passes. The text begins with !so.

Use first word is for chat commands so !so does not also fire on !sound.

Upper and lower case (Aa)

With Aa on, Message first word is !lurk also matches !Lurk and !LURK. Turn it off when case matters, for example to match an exact reward ID. Conditions made in older versions of Mycelian open with Aa off, because they used to match case exactly.

AND and OR

Rows joined by AND must all match. OR starts a new group, and the connector runs when any one group matches. AND binds tighter than OR, so A and B, or C means (A and B) or C. The summary line always shows the grouping.

AND: a range.

OR: either case.

To say A and (B or C), repeat A in each group: A and B, or A and C. Removing the first row turns the next one into the new where row.

Using the rest of the message

When a condition on Message uses contains, first word is, starts with or ends with, Mycelian removes the matched text and keeps the rest in {message_after_conditions}. This turns a chat trigger into a command with arguments.

What conditions cannot do

Conditions only compare details that the event carries. These are not available:

  • Subscriber or VIP checks. Chat events offer Is a moderator (true for mods and the broadcaster); badges are only a variable, {badges}.
  • Time of day or day of week. To run at a time, use the At a set time trigger.
  • "First time" checks such as a viewer's first message. For that, see Chatbot Greetings.

To stop a connector running too often, use Cooldown on the trigger card rather than a condition.

Troubleshooting

The condition never passes
  • Check Aa. With it off, capitals must match exactly.
  • Read the summary line: an OR in the wrong place changes the meaning.
  • Sub tiers are 1, 2 or 3.
  • Number comparisons fail when either side is not a number, such as $5. Use Amount, not Amount as shown.
  • With first word is, the value must be the whole first word. Use starts with to match part of it.
Test says nothing ran, but real events work

Test uses fixed sample data, for example 100 bits or the chat message !hello there. If your conditions exclude those values, it reports Test event didn't pass the conditions, so nothing ran. See Connector System Introduction for the sample values.

The connector fires too often

Add a narrower condition, for example a minimum Amount, or first word is instead of contains on chat, or set a Cooldown. On Any event, always add a condition on Event type.
