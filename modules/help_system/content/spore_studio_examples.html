Ten small overlays, each with what it looks like on stream and how it is built. Pick one from the tabs. Field details are in Designing Templates and action arguments in Event Bindings & Actions.

Every example starts with + New in the Spore Studio toolbar. The New template dialog asks for Name, Alert system, Copy from existing, Width (px) and Height (px). Add the finished overlay to OBS as a browser source at http://127.0.0.1:5000/ followed by the template name.

Examples

How it's built

  1. + New → Name follow_alert, Alert system Queue, 800 × 200.
  2. Drag in a Container. Put the rest inside it.
  3. Text (category label) with Text New follower!.
  4. Text (category username), left empty. A binding fills it.
  5. Image (category avatar) pointing at a picture in assets/follow_alert/.
  6. Select the username text → Bindings → + Add binding:
    • Trigger Registry event, Event Alert (queue)
    • Filter: Alert type = follow
    • Action Set text content, Payload field username
  7. Select the container → binding on the same event and filter → Action Show for N seconds: Seconds 5, Entrance and Exit fade.
  8. The container starts hidden on its own because it has a Show binding (Visibility → Start hidden until shown).
  9. Tick the Expose in Source Settings box next to any color or font you want to change later without the editor.
  10. Save → Preview → click the follow mock.

Queue templates play in step with Mycelian's alert queue. Whether this overlay should also report completion is explained under alert_complete in Advanced JS.

How it's built

  1. + New → sub_counter, Alert system Instant, 600 × 80. Instant does not hold the alert queue.
  2. Drag in a Counter (Widgets group).
  3. In Counter: Counter id sub_count, Initial value 0, Format Subs: {value}.
  4. Data feed → + Add feed:
    • 1. When it runs: Alert (instant) only
    • 2. Which ones to keep: Alert type New sub
    • 5. Update this block: Add to this counter, Delta kind fixed, Value 1
  5. Optional: turn on Persist (database) to keep the total between streams.
  6. Save → Preview → Sub.

How it's built

  1. New template. Either alert system works; chat does not use the alert queue.
  2. Add a Text block.
  3. Binding: Event Chat message (Twitch), Action Set text content, Payload field message.
  4. + Add chained step: delay 0, Action Show for N seconds, Seconds 4.
  5. Optional: Filter: Message type = text to skip /me actions.

The same thing with feeds: one feed on Chat message (Twitch) with Main text field message and Replace this text, and a second feed on the same event with Show for a few seconds.

How it's built

  1. Add a Video block. Set Visual kind to image for a GIF, or video for a clip.
  2. Drop the GIF and sound into the template's asset folder (Assets → Upload). Put the sound in Optional audio URL.
  3. Binding: Event Alert (queue), Filter: Alert type = bit (or donation), Action Set visual source (GIF/video) with Literal URL /assets/cheer_gif/cheer.gif.
  4. + Add chained step: delay 0, Action Play audio element. It plays this block's audio.

How it's built

  1. Group the alert art in a Container.
  2. Binding on the container: Event Alert (queue), Filter: Alert type = follow, Action Randomize position within bounds: X min 0, X max -1, Y min 0, Y max -1. -1 means the canvas edge.
  3. + Add chained step → Show for N seconds.

How it's built

  1. Stream Deck tab → + Add Stream Deck action: Action id toggle_logo, Display name Toggle logo, Socket event toggle_logo, default_data {}.
  2. Select the logo Image → binding: Trigger Stream Deck action → Toggle logo, Action Toggle visibility.
  3. Preview → SD: Toggle logo to test.

How it's built

Binding on Alert (queue) (any type), primary Action Show element, then + Add chained step three times:

Chain stepDelay before this step (ms)ActionArgs
1100Play CSS class animationClass name sporePop, Hold (ms) 400
2450Play CSS class animationClass name sporeShake, Hold (ms) 420
33000Hide element—

Each step waits its delay after the previous step, then runs. A binding can have at most 15 chained steps.

How it's built

  1. + New → my_bits, Alert system Instant, 300 × 55. Or set Copy from existing to bitcounter.
  2. Counter block: Counter id bit_count, Format {value}, Initial value 0.
  3. Feed: Alert (instant), Alert type Bits, Add to this counter, Delta kind data_source → Bits cheered.
  4. Image block → Image source mode From counter (ranges) → Counter bit_count. Ranges 0–99 cheer1.gif, 100–999 cheer100.gif, 1000–4999 cheer1000.gif, and so on, from /assets/my_bits/.
  5. Range change transition: Animate when image changes, Roll out, then roll in, 600 ms.
  6. Save → Preview → Bits.

The built-in bitcounter also counts up with a 1000 ms tick-up. Copying it keeps that. Details in Counters.

Before you go live

  • Preview each event you bound, using the mocks under Alerts:, Other: and SD:.
  • Save, then refresh the browser source in OBS.
  • Queue templates behave with the alert queue. See Advanced JS.
  • Counters keep or reset their value as you intended. See Counters.
  • Data displays update on the events you chose. See Data Sources.
  • Stream Deck keys do the same thing as the SD: buttons. See Stream Deck.
  • Dynamic controls work from the Source Controls tab.
