A Counter block shows a number that changes on its own: bits cheered, subs this stream, a game score. Its Data feed decides when it changes and by how much. It can stay between streams, count toward goals, and swap images as it grows.

When to use a counter

BlockBest for
CounterRunning totals that add, subtract, set or reset on events. Can persist, use goals and drive images and progress bars.
Text with a Set text content bindingShowing one payload field as it arrives, such as the latest username
Data displayShowing a live value without arithmetic, such as session bits. See Data Sources.

Set Alert system to Instant (instant_alert) on the Canvas tab for counter HUDs. Instant alerts update the overlay without holding the alert queue.

Set up a counter

Drag a Counter block onto the canvas

It is in the Widgets group of the Blocks panel. Pick a category when asked (for example Counter).

Fill in the Counter section

With the block selected, open Counter on the Properties tab.

  1. Counter id is what images, progress bars, bindings and Source Controls use to find this counter. Spaces and symbols become _.
  2. With Progressive goals off you get a single Max. Leave Min or Max empty for no limit. Goals are explained below.
  3. Format is the text shown. {value}, {min} and {max} are replaced. The checkbox next to it exposes the format in Source Settings.
  4. Persist (database) keeps the value between reloads. See Persist below.

The Appearance section adds Scroll, Scroll speed (s), Scroll direction and Scroll gap (px) if the number should move across the block like a marquee, plus the usual text styles.

Add a feed for each thing that changes it

Open Data feed and click + Add feed. A counter feed starts on Alert (instant) and Alert (queue) with Add to this counter. This feed adds bits on every cheer:

Under Update this block a counter offers:

ChoiceEffect
Add to this counterAdds the amount. Uses 1 when no number is mapped.
Subtract from this counterSubtracts the amount
Set this counterReplaces the value
Reset this counterReturns to Initial value
Show, hide, toggle and the other shared choicesSame on every block. See Data feeds.

Save and test

Click Save, open Preview, and click a mock under Alerts: (for example Bits or Sub). The number should change. Click Reload in the preview to check persistence.

The amount: Delta kind

Delta kindFieldsUse for
fixedValue+1 per sub, +10 per raid
random_intMin, Max (inclusive)Random whole numbers
random_floatMin, Max, DecimalsRandom decimals
data_sourceSource, extra source fields, FallbackA live number such as Bits cheered (alert.amt_cheered)

For alert and subscription sources, Fallback is used when the alert does not match. 0 leaves the counter unchanged. The source list hides text-only sources. See Data Sources for every source.

Event Alert (instant) · Alert type Bits · Add to this counter · Delta data_source → Bits cheered. This is how the built-in bitcounter template works.

Event Alert (instant) · Alert type New sub · Add to this counter · Delta fixed → 1.

Event Alert (instant) · Add to this counter · Delta data_source → Gift sub (+quantity). It returns the gifted quantity for gift-sub alerts and the fallback for everything else. Add a Tier filter to count one tier only.

Persist (database)

With Persist (database) on, the value is stored in Mycelian's database and survives overlay reloads and restarts. Two more fields appear:

FieldDefaultPurpose
DB path<template name>/countersDatabase document that stores the counter
DB keyThe counter idKey inside that document

With it off, the counter goes back to Initial value every time the browser source reloads.

Persist marathon or all-time totals. Leave it off for per-stream counters, or reset them from Source Controls.

Progressive goals

Turn on Progressive goals to replace the single Max with a list, such as 100, then 200, then 300. The first goal starts at the old Max (or 100). + Add goal adds the next one at the same spacing. Each goal must be at least the one before it.

The count is never reset when a goal is reached. {max}, and any progress bar driven by this counter, move to the next goal instead. Click a count to see it:

  • Once a goal is reached, the count cannot fall below it.
  • The count cannot rise above the last goal.
  • Reset returns the count to the initial value and the first goal.
  • Reaching a goal emits goal_reached with the goal, the next goal and its index. One update that skips past two goals emits one event per goal.
  • The progress bar's own goal_reached fires only when the bar is full, which is at the last goal.

Value change animation

Separate from Entrance / Exit animations, a counter can animate each time its number changes. The settings live in the Value change animation group:

FieldPurpose
Enable on value updateRun an animation when the displayed value changes
Animation typeTick up (count) counts from the old value to the new one. fade-in, slide-in and bounce are visual effects.
Duration (ms) / EasingTiming. Default 500 ms, ease-out.
Continuous pulseKeep pulsing while the value is displayed. Can be distracting during cheer trains.

In this version the group is not shown under Counter blocks in the editor. Templates that already have it set, such as bitcounter (Tick up, 1000 ms), keep the effect.

Images that change with the count

An Image block can pick its picture from a counter value, for example a bigger cheer gem as bits add up.

  1. Set Image source mode to From counter (ranges).
  2. Pick the Counter.
  3. Click + Add range for each step. Min and Max are whole numbers and both are inclusive. Pick an image from assets/<template name>/.
  4. Set Default src (fallback) for values outside every range.
  5. With two or more ranges, Range change transition appears. Types: fade, slide, crossfade, bounce, roll. Default 400 ms.

The built-in bitcounter uses six ranges and a 600 ms roll:

Changing a counter from somewhere else

A counter's Data feed listens to Mycelian events. For anything else, use one of these:

FromHow
A Stream Deck keyBinding with trigger Stream Deck action and action Adjust counter. See Stream Deck Actions.
A binding chainAdjust counter as a chained step, for example after Show for N seconds. See Bindings.
Source ControlsA Counter control, which gives you an amount box with -, + and Reset. See Dynamic Controls.

The Adjust counter binding action takes these arguments:

ArgLabelPurpose
counter_idCounter idTarget counter
operationOperationincrement, decrement, set, reset
delta_kindDelta kindfixed, random_int, random_float, data_source
delta_valueFixed delta / fallbackFixed amount, or the fallback for a data source
delta_sourceData source idFor data_source, for example alert.amt_cheered
delta_min, delta_maxRandom min / maxRandom range (defaults 1 and 5)
Where did counter rules go?

Older templates stored "counter rules" on the counter. Spore Studio now turns each rule into a Data feed with the same event, filters and delta when you save, and the rules list is cleared. Old Stream Deck rules become feeds that match the action name.

Other templates need to know when my counter changes

Counters publish counter_changed (with the counter id, value and change) and, with goals, goal_reached. Turn them on or off and rename them in the block's Outputs section. Other templates pick them under The output of another template. See Data feeds.
