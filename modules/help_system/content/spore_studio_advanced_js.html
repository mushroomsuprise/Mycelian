Use the Advanced JS tab when a binding or data feed cannot do what you need. Your script is saved into the overlay and kept across saves, and it can call the same helpers the generated code uses.

The editor

Short scripts fit in the box on the tab. {{icon:open_in_new}} Expand editor opens a larger editor for the same script.

  1. Find opens find and replace (also Ctrl/Cmd+F). Reference opens the helper list. Done closes the editor.
  2. Insert helper: click an entry to insert a ready-made snippet at the cursor.
  3. Cursor position and length of the script.

The editor has line numbers, Tab indent, matching brackets and syntax coloring. Both editors edit the same script. Closing the large editor, or pausing while you type, records an undo step.

Where your script goes

On Save, Mycelian writes the overlay script in three marked regions:

MarkersWhat happens on Save
SPORE_STUDIO:data-runtime-begin … data-runtime-endThe shared helper library. Replaced from the boilerplate.
SPORE_STUDIO:auto-begin … auto-endRebuilt from bindings, counters, feeds and widgets. Do not edit it.
SPORE_STUDIO:user-begin … user-endYour script, kept exactly as you wrote it

Your script runs in the same page script as the helpers, after them, so socket and every function below already exist.

Globals

  • socket is the overlay's Socket.IO connection.
  • window.__sporeLastPayload.event is the last event payload. Data displays and stat cards read it.
  • window.__sporeLastPayload.wheel is { elementId, index, label } after a wheel stops. The overlay also sends wheel_result with it.
  • window.__sporeTwitchCache holds Twitch API responses by requestId.
  • MycelianLog.info(msg), MycelianLog.warn(msg) and MycelianLog.error(msg) write to mycelian.log under this template's name. Uncaught errors, console.warn and console.error are sent there too.

Recipes

Add listeners next to the generated ones. Do not replace the generated socket.on handlers.

socket.on('instant_alert', function (data) {
    if (!data || data.alert_type !== 'bit') return;
    sporeShow('thank_you');
    sporeSetText('who', data.username || '');
    sporeCounterAdjust('bits', 'increment', {
        kind: 'data_source',
        source: 'alert.amt_cheered',
        alert_type_filter: 'bit',
        fallback: 0
    }, data);
});

If you handle an event yourself and want data displays to follow, set window.__sporeLastPayload.event = data and call sporeRefreshAllDataDisplays().

A Queue template handles the alert queue for you. It lines up each next_alert, runs your bindings, holds for the template's Duration (or the alert's duration) and while its media plays, and then reports the alert done. It does this only when the template is one of the alert's queue_holders; otherwise it just watches.

Do not send alert_complete yourself in a Queue template. The template already does, and an extra one ends the alert early. The Canvas tab dropdown label emit alert_complete in Advanced JS, the same hint on the Queued card in the New template dialog, and the Reference snippet date from before this was automatic. Use Duration on the Canvas tab to control how long the alert holds.

A socket.on('next_alert', …) listener in your script runs as soon as the alert arrives, not when the template's own queue reaches it. For per-alert visuals, prefer bindings, which run in queue order.

A Source Control with action my_action on template my_overlay sends my_overlay_my_action. Listen for that name:

socket.on('my_overlay_my_action', function (data) {
    sporeSetText('banner', (data && data.value) || 'clicked');
});

See Dynamic controls.

Prefer a Twitch API binding when the request belongs to one element. From script, send the request and read the answer yourself:

socket.emit('twitch-api-request', {
    endpoint: 'https://api.twitch.tv/helix/users',
    method: 'GET',
    requestId: 'my-follower-check',
    params: { login: 'someuser' }
});

socket.on('twitch-api-response', function (data) {
    if (!data || data.requestId !== 'my-follower-check') return;
    window.__sporeTwitchCache['my-follower-check'] = data;
    sporeRefreshAllDataDisplays();
});

A data source of type Twitch API response field reads that cache. Ids Spore Studio makes for bindings look like spore_tw_elementId_0.

sporeDbGet('my_overlay/counters', function (doc) {
    doc = doc || {};
    sporeSetText('note', String(doc.note || ''));
});

sporeDbSet('my_overlay/counters', { note: 'saved from the overlay' });

Persisted counters use {template}/counters by default, keyed by counter id.

Counters and lists

Prefer a Counter's Data feed when the math is "add this field on this alert". Use sporeCounterAdjust when the change depends on something the feed editor cannot see, such as a calculation, a timer or a Twitch response.

A List with no Data feed stays empty until a binding or sporeListAdd adds rows. A List with a feed (alerts, giveaways, any event) fills itself.

Pitfalls

My edits disappeared after Save

They were inside auto-begin … auto-end, which is rebuilt on every save. Put your code between user-begin and user-end, which is what the Advanced JS tab edits.

Alerts end too early, or the queue skips ahead

Remove any socket.emit('alert_complete', …) from a Queue template's script; the template already sends it. Raise Duration on the Canvas tab if the alert needs longer.

A counter jumps on unrelated alerts

Give the data-source delta fallback: 0 and an alert_type_filter, so other alert types add nothing.

sporeShow does nothing

The id must match the element's ID in Properties exactly, including case.

An error says socket is not defined

The boilerplate creates socket before your block. If you still see this, wrap the code in if (typeof socket !== 'undefined') { … }. Check mycelian.log for the full error; overlay errors are logged under the template name.
