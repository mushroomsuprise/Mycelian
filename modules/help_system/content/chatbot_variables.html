Variables are names in curly braces. When the chatbot sends a reply, it swaps each one for a real value: {username} becomes the viewer's name. Click any variable on this page to copy it.

{{icon:data_object}} Reference {{icon:place}} ChatbotCommands / EventsVariables

Variables work in the reply of commands and events, and also in a lookup's fallback text, an input's If empty text and lookup text boxes. Greetings use the same variables too (without command words and lookups). Quote replies, giveaways and polls have their own short lists, shown in the last tab below.

Inserting variables

  • { } button: every box that takes variables has one. It opens a searchable list, grouped, with an example value for each. Click one to insert it at the cursor.
  • Variables panel: the list on the right of the editor. Click a variable to insert it where your cursor last was. If no box has been clicked yet, it is copied instead and Mycelian says Click into a text field to insert variables there.
  • Dates and times: date variables show format… in the list, or a {{icon:tune}} button in the panel. Pick a ready-made format or type your own under Custom; the variable is inserted as {time:%-I:%M %p}.

The editor checks your reply as you type. A name it doesn't know gets Not a variable here, so it is posted as written: {usr} (did you mean {username}?), and the card shows Check {usr}.

How variables work

You writeYou get
{username}, {amount}…The value. A known variable with no value, such as an empty sub message, becomes empty text.
{time:%H:%M}, {followed_since:%b %-d}A date or time in your format. Works on {time}, {date}, {datetime}, {timestamp} and date variables such as {followed_at} or a lookup's {live_since}.
{amount:,}, {amount:.2f}A formatted number: 1,234 or 12.50.
{time.12.ampm}The older time filters still work. See Date and time formats below.
{UserName}, {usr}Names must match exactly. An unknown name is posted as written, braces and all.

Variables are filled in once. If a viewer types {stats.alerts.total_bits} after your command, it is posted as they typed it, not filled in.

Date and time formats

The format list offers: 24-hour time (19:30), 12-hour time (7:30 PM), Time with seconds, ISO date (2026-03-14), Short date (Mar 14), Long date (Saturday, March 14, 2026), Day name, Month name, Year and Date and time (Mar 14, 7:30 PM). Under Custom, type your own with these codes; the example underneath updates as you type.

CodeGivesCodeGives
%HHour, 24-hour (19)%A / %aWeekday (Saturday / Sat)
%-IHour, 12-hour (7)%B / %bMonth (March / Mar)
%M / %SMinute / second%-dDay of the month (14)
%pAM or PM%YYear (2026)

The - drops the leading zero (7:30, not 07:30) on Windows and macOS alike. Example: {time:%A at %-I:%M %p} → Saturday at 7:30 PM.

The older {time.…} filters

Add filters to {time} with dots, in any order: 12 / 24 (clock), ampm / noampm, sec / nosec, a layout (hh:mm, h:mm, hh:mm:ss, h:mm:ss), a zone (UTC EST EDT CST CDT MST MDT PST PDT) and tz to show the zone name. For example {time.hh:mm.12.ampm} → 07:30 PM, {time.UTC.tz} → 00:30:45 UTC.

Custom variables

A custom variable is a small calculation or rule you can reuse in any command or event as {custom_name}. Click New custom variable in the Custom group of the Variables panel.

  1. The name: lowercase letters, digits and _, starting with a letter. It can't be changed after the variable is created.
  2. Pick a kind. Each kind shows its own boxes, and every box has a { } button.
  3. The value right now, using sample values. When something is wrong the box turns red and says why, for example The first value is “TestViewer”, not a number or Can't divide by zero.
KindExampleResult
Math: two values with + add, − subtract, × multiply, ÷ divide or random between (the boxes become Lowest and Highest; a new number every time), and Round to (Don't round, Whole number, 1 or 2 decimals){custom_hours_live}: {stats.session.session_duration} ÷ 3600, 1 decimal2.5

Twitch data: one value from A Twitch lookup (what to look up, about whom, which value) or An API request (advanced) (a Helix path, parameters, and the field to use from the first result), plus If it fails text{custom_follow_days}: How long someone has followed, about whoever triggered the reply, use {follow_days}812
  • A custom variable is worked out each time a reply is sent, with that reply's values: {username} is the chatter or event viewer, and {count}, inputs and lookup variables are available when the command has them.
  • Twitch data is fetched when a reply uses the variable, with your connected Twitch account, and kept for 30 seconds. The editor preview uses example data. To change a Twitch value (say, days to weeks), use the Twitch data variable inside a Math or If / else variable: {custom_follow_days} ÷ 7.
  • Math only works with numbers: in a reply, a value that isn't a number (or dividing by zero) gives 0. If / else compares numbers when both sides are numbers, otherwise text, ignoring upper and lower case.
  • Custom variables are shared by every command and event, and can use each other. Click {{icon:edit}} next to one in the Custom group to edit it or Delete it.
  • Variables made with the old expression box open as Expression (Written by hand) and keep working, including math(), compare(), if() and date_to_age().

Troubleshooting

The variable shows up as {something} in chat
  • Check the spelling and use curly braces, not parentheses. The editor warns about unknown names and the card shows Check {…}.
  • Check that it applies here: {count} only on counters, event values only on the matching event, lookup values only when the item has that lookup.
The preview looks right but chat is different

The preview and Test use sample values (TestViewer, 100 bits, example lookup results). Real replies use the real event, and lookups ask Twitch.

A statistic is always 0

Statistics start counting from the moment the feature is used. Check the total on SettingsStatistics, and check the name against the Statistics tab above.
