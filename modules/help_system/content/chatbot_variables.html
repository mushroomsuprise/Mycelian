Variables are placeholders in curly braces. When the chatbot sends a message, it swaps each one for a real value: {username} becomes the viewer's name. Click any variable on this page to copy it.

{{icon:data_object}} Reference {{icon:place}} ChatbotCommands / EventsVariables panel

Variables work in the Response Text of commands and events. Greetings, giveaways and polls have their own short lists, shown in the last tab below.

Where to find them in the app

In the editor, click a variable to add it to the end of Response Text. Preview above the text box shows the result with live or sample values in italics.

The list changes with the command type and event type you pick, so it only shows what fits.

Spelling must match exactly, including underscores. Unknown variables are left in the message as plain text.

Add filters to {time} with dots, in any order. Capitals do not matter.

FilterEffect
12 / 2412-hour or 24-hour clock. 24 is the default.

tzAdd the zone name. Without a zone filter it shows your computer's zone.

The Variables panel lists per-channel variables without the youtube. prefix, for example {mycoolchannel_latest_video_url}. Add youtube. after the opening brace so it is filled in chat.

A custom variable is a saved expression you can reuse in any command or event. Create one with Custom Variable in the Variables panel. Give it a Variable Name and an Expression, then click Create Variable. Mycelian adds custom_ to the front of the name.

FunctionWhat it doesExample
math(…)Arithmetic with + - * / ** % and round, min, max, abs, int, float. Errors give 0.math({stats.alerts.raids} * 2)
compare(a, op, b)True or False. Operators: > < == != >= <=compare({stats.chatbot.commands_triggered}, >, 100)
date_to_age(…)Age of an ISO date as N years, M daysdate_to_age(2021-01-01T00:00:00Z)

Expressions can contain statistics, YouTube, time, other custom variables (up to 10 levels deep) and the command word variables ({command_message}, {command_word_1}…). Argument mappings such as {city} are not filled inside a custom variable; use them in the response text. Mycelian rejects an expression that uses a variable it does not know.

Inside a custom variable, {username} is your own channel name, not the viewer, and {date} reads like October 22, 2026. Put {username} in the response text instead.

Custom variables are shared by all commands and events. Edit or delete them from the Custom group in the Variables panel.

Listed but not filled in chat

A few entries in the Variables panel only fill in on the Preview. In a real chat reply they stay as plain text:

  • {datetime}. Use {timestamp}.
  • {command_name} and {last_used}.
  • The Quotes group, such as {quote.id.text}. Use the built-in !quote command.
  • Event extras such as {tier_name}, {streak}, {follower_count}, {raider_name}, {gifter_name}, {reward_cost} and {user_input}. Use the values in the Events tab above.
  • {account_age.days} and the other dotted account-age names. Use the underscore names in the API tab.

Examples

!so      → Go check out {command_word_1}! They were last seen streaming great things.
!bits    → This channel has received {stats.alerts.total_bits} bits. Thank you!
!time    → It is {time.hh:mm.12.ampm.tz} for the streamer.
!video   → Latest video: {youtube.latest_video_title} {youtube.latest_video_url}
Raid     → Welcome {username} and the {viewer_count} raiders!

Troubleshooting

The variable shows up as {something} in chat
  • Check the spelling and use curly braces, not parentheses.
  • Check that it applies here: {count} only on Counter commands, event values only on the matching event type.
  • Check the "Listed but not filled in chat" list above.
The preview looks right but chat is different

The preview uses sample values (for example PreviewUser, 100 bits) and your own name. Use Test on the card to send a real message.

A statistic is always 0

Statistics start counting from the moment the feature is used. Check the total on SettingsStatistics, and check the name against the Statistics tab above.
