The trigger is the event that starts a connector. Each connector has one. You pick it in the editor's first step, When · Trigger.

The trigger also decides two things: which Field choices you get for conditions, and which variables, such as {username}, hold real data in your actions. The editor's Variables panel always shows the list for the trigger you picked.

Choosing a trigger

A new connector opens on this list. Click a trigger to pick it. Once picked, the step shows a trigger card:

  1. Cooldown: after the connector runs, new events are ignored for this many seconds. 0 means no cooldown. It also applies to Test.
  2. Change opens the list again (with Cancel to keep the current trigger). Conditions that the new trigger can't check are removed, and Mycelian tells you how many.

Twitch triggers need Twitch connected, YouTube triggers need YouTube connected, tips need Streamlabs, StreamElements or YouTube, and OBS triggers need OBS WebSocket. The connector card uses the same trigger names as this list; its icon shows the service, so a Twitch and a YouTube Chat message are told apart by their icons.

Hotkey

  1. Type the combination joined with + (ctrl+shift+f, f12, alt+tab), or click Record, hold the modifiers and press the key. Esc cancels recording. Mycelian tidies what you type: Ctrl + Shift + B becomes ctrl+shift+b, and option, win or command become alt or cmd.
  2. Another connector already uses this combination. That's allowed: one press runs every connector with that hotkey.

Hotkeys always work globally, while your game or another app has focus. The modifiers must match exactly: ctrl+f does not fire for Ctrl+Shift+F. Variables: {combo}, {key_code} (the main key) and {modifiers}.

Stream Deck button

The editor shows: In the Stream Deck app, add the Mycelian Connector action and pick “your connector's name”, followed by its connector ID. Save the connector first so the plugin can list it. See Connect Stream Deck.

Webhook

  1. Copy puts the URL on the clipboard. New key makes a new secret key; the old URL stops working once you save.

Use it from any tool that can call a web address, such as a script, a home-automation app or another bot:

curl -X POST "http://127.0.0.1:5000/api/connectors/webhook/CONNECTOR_ID" \
  -H "X-Mycelian-Key: YOUR_KEY" -H "Content-Type: application/json" \
  -d '{"username": "Sam", "amount": 5, "message": "Door opened"}'
  • Send the key either as the X-Mycelian-Key header or as ?key= in the URL. The header keeps it out of logs.
  • A simple GET works too: …/webhook/CONNECTOR_ID?key=YOUR_KEY&username=Sam.
  • Every field you send becomes a variable ({username}, {amount}, {anything_else}), and {payload} holds everything as JSON. Conditions can check username, message and amount.
  • The reply is {"ok": true}, or an error: wrong or missing key (401), no such connector (404), connector turned off (409).

Every few minutes

The first run comes one interval after Mycelian starts or the connector is turned on. Good for reminders such as follow the socials every 20 minutes. Variables: {interval_seconds}.

At a set time

The time is required; until it is set the editor says Set the time the schedule runs (HH:MM). Variables: {specific_time} and {days_of_week}.

Timers, set times, hotkeys and Stream Deck buttons have nothing to check, so the If · Conditions step says This trigger has nothing to check, so it always runs.

Any event runs for every event from every service: bits, chat, subs, OBS changes, hotkeys, Stream Deck presses and more. The editor warns:

Runs for every event from every service, including each chat message. Add a condition on Event type to narrow it down.

Its Field list has Event type plus the fields of every other trigger. An event that doesn't have a field fails a condition on it, except is not and does not contain, which pass. Variables: {event_type} (for example twitch_chat_message), and {username}, {message} and {amount} when the event has them.

What triggers can't do

  • Chat commands: there is no separate command trigger. Use Chat message with the condition Message first word is !yourcommand. See Conditions. For simple replies, Chatbot Commands may be easier.
  • Two triggers on one connector: a connector has one trigger. Make one connector per trigger (Duplicate on the card helps), or use Any event with Event type is … conditions joined by OR.
  • "10 follows in 5 minutes" style thresholds do not exist.

Variables from the trigger

Besides the trigger's own variables above, these work with every trigger:

VariableValue
{connector_name}, {trigger_count}, {trigger_type}This connector's name, how many times it has run (this run included), and the trigger's internal name such as twitch_bits
{time}, {date}, {datetime}, {triggered_at}Now, in local time ({triggered_at} is the same moment in Unix seconds). All four take a date format, e.g. {time:%-I:%M %p} gives 7:30 PM.
{message.word.1}, {message.word.2}…The Nth word of the message
{message_after_conditions}The message with the text matched by your Message conditions removed. See Conditions.
