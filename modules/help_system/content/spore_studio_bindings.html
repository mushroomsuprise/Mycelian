A binding makes an element react to something: a Mycelian websocket event such as an alert, or a Stream Deck key. Each binding has a trigger, optional filters, one action, and up to 15 chained steps.

{{icon:place}} Spore StudioBindings

For canvas and property basics, see Designing templates. To drive a block continuously from live values, a Data feed is often simpler than a binding.

Add a binding

Select the element

Click the element on the canvas or in the Outline, then open the Bindings tab. With nothing selected the tab says Select an element to attach event bindings.

Click + Add binding and pick a trigger

Trigger is Registry event (listens to Mycelian) or Stream Deck action (listens to a hardware key). Then pick the Event, or the Stream Deck action.

Narrow it with filters (optional)

Each field the event carries gets a Filter: row. Leave a row blank to match anything. Type a value to fire only when that field equals it.

Choose the action

Pick the Action and fill in its fields. Add Chained actions if more should happen after it.

Test in Preview

Click Preview and fire mock events. Bindings work in the preview before you save. See Live preview.

The binding card

  1. Trigger and Event. The event's description appears under the dropdown.
  2. One Filter: row per payload field. The placeholder shows example values when the event has them.
  3. Action and its fields. The action's description appears under it.
  4. Chained actions run after the main action, in order, each after its own delay.

Triggers

A curated list of Mycelian socket events that are useful to overlays. Internal plumbing is left out. Outputs from other templates, such as a wheel's wheel_result, are added to the list automatically with the template name in the label.

Runs when a Stream Deck key mapped to one of this template's actions is pressed. Add actions on the Stream Deck tab first; until then the binding says Add Stream Deck actions in the Stream Deck tab first. New bindings default to the first action not already used. The card shows the Socket event that action sends. See Stream Deck actions.

Filters

A filter row compares the payload field with what you typed, exactly. Leave it blank to match anything.

EventFilterFires for
Alert (queue) / Alert (instant)Alert type = followFollows only. Other types: sub, resub, giftsub, bit, donation, raid, hype_train, point, streak.
Alert (queue) / Alert (instant)Sub tier = 3000Tier 3 subs
Chat message (Twitch)Message type = action/me messages. Also text, highlight.
Chat message (Twitch)Username = StreamerNameOne user, exact spelling
Chat moderation eventAction = timeoutTimeouts. Also delete, ban.

Event filters compare as text. They work on text fields such as alert type, tier, username, message type and action. A value typed for a number or true/false field (for example Paused or Amount) does not match. For those, use a Data feed filter or Advanced JS. Twitch API response filters are different: their values are read as JSON, so true works there.

Examples

Show a follow alert for 5 seconds with a fade

Event Alert (queue), Filter: Alert type follow. Action Show for N seconds: Seconds 5, Entrance fade, Exit fade. Turn on Start hidden until shown on the element so it does not flash on load.

Write the alert's username into a text block

Action Set text content, Payload field username. To show a fixed message instead, leave Payload field blank and type it in Literal text, such as Welcome to the stream!

Pop up somewhere random in the lower part of the canvas

Action Randomize position within bounds: X min 0, X max -1, Y min 400, Y max -1.

Add bits to a counter

Event Alert (instant), Filter: Alert type bit. Action Adjust counter: Counter id bit_count, Operation increment, Delta kind data_source, Data source id alert.amt_cheered.

For "add this field on this alert", a Counter block's Data feed is usually simpler. Use Adjust counter when the change is part of a chain or comes from another trigger, such as a Stream Deck key.

Show, shake, then hide

Action Show element. Chain step 1: delay 200, Play CSS class animation sporeShake. Chain step 2: delay 3000, Hide element.

Chained actions

Click + Add chained step to run more actions after the main one, up to 15 steps. Each step has Delay before this step (ms) and its own Action.

The delay counts from when the previous step starts, not from when its animation ends. A Show for N seconds step runs its own hide timer, separate from the chain delays.

Twitch API bindings

Pick Twitch API call (response) as the event to have the overlay call the Twitch Helix API once after it connects, then run the action when the answer matches.

FieldPurpose
EndpointFull Helix URL. Must start with https://api.twitch.tv/.
MethodGET, POST, PUT, PATCH, DELETE
JSON parameters (query)Optional JSON object added to the URL as query parameters
JSON bodyOptional JSON body for POST, PUT and PATCH
Response filtersRows of payload field and value. Values are read as JSON (true, false, numbers). Leave a key empty to ignore the row, or a value empty to match any.

Spore Studio gives each binding a fixed requestId (like spore_tw_elementId_0) and adds it to the filters, so the binding only reacts to its own answer. For calls outside bindings, see Advanced JS.

Legacy templates

Hand-written templates manage their own websocket code. Their Bindings tab says Legacy templates manage their own websocket bindings inside the hand-authored HTML — bindings are not editable here. See Legacy templates.
