Actions are what a connector does once its trigger fires and its conditions pass. A connector needs at least one action and can have as many as you like.

How actions run

  • Actions run in order, Action #1 first.
  • From Action #2 on, Delay (s) is how long to wait after the previous action before this one starts. Delays add up: 2 s then 5 s means the third action starts 7 s after the first.
  • If an action fails (for example OBS is not connected), the next actions still run. The failure is written to the log.
  • Text fields accept placeholders such as {username} (see Placeholders below).
  1. Action Type picks the action. The fields below change to match.
  2. Per-action settings. Here: which chats get the message.
  3. Delay (s) appears on every action after the first.

Game Hook (memory write) changes a running single-player game, for example adding gil when someone redeems channel points. Pick the Game (Final Fantasy VII (2013)) and an operation, then fill in its fields.

If an enabled Game Hook action's hook is off or not attached to the game, the whole connector is skipped, not only that action.

Supported games, operations and their extra placeholders ({random_character}, {random_enemy}, {random_damage.1.9999}…) are on Game Hooks.

Placeholders

Write a field name in single braces, with no spaces: {username}. Mycelian replaces it with the event's value when the action runs. The old double-brace form {{username}}, which some field hints still show, also works.

PlaceholderValue
{username}, {amount}, {message}…Any field of the trigger's event. The list per trigger is on Connector Triggers.
{message.word.2}The 2nd word of the message
{message_after_conditions}The message with the text matched by your Message conditions removed
{message_after_word.1}The 1st word of that remaining text
{message_after_from_word.2}The remaining text from its 2nd word to the end
{event_type}, {source}, {timestamp}, {triggered_at}Event details
{connector_id}, {trigger_id}, {trigger_type}Identifiers for this connector
{action1.item_name}, {action1.quantity}, {action1.resolved_name}, {action1.error}Results from an earlier action (game hook queries). The editor lists them as Prior action outputs from Action #2 on.

A placeholder with no value, or a misspelled one, becomes empty text. If a message comes out with gaps, check the spelling against the trigger's field list.

Card labels

The connector card names each action briefly, for example Send Chat Message → All, Send Announcement (purple), OBS: set program scene, Write to chat.log or GET → example.com. Search on the Connectors tab matches these labels.

Good practice

  • Build one action, test it, then add the next.
  • Give overlays time: put a Delay (s) before an action that depends on a scene or banner from the previous one.
  • Keep chat replies short and rare. Add conditions so a busy chat does not trigger a flood.
  • Keep viewer text away from Execute Command and Key Press.
  • If actions cause lag, see Performance Optimization.
