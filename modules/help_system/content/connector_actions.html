Actions are what a connector does once its trigger fires and its conditions pass. A connector needs at least one action and can have as many as you like. You add them in the editor's third step, Then · Actions.

How actions run

  • Actions run in order, top to bottom, one after another.
  • Every action, the first one too, has Wait … seconds before this action runs. Waits add up: 2 s on action 2 and 5 s on action 3 means action 3 starts about 7 s after action 1.
  • An action whose switch is off is skipped but kept, so you can turn it back on later.
  • If an action fails (for example OBS is not connected), the next actions still run. The failure is written to the log.
  • Text fields accept variables such as {username} (see Variables below).
  1. The card header: number, action name and a one-line summary filled in with example values. When a folded card is missing something, the summary turns orange and says what, e.g. Banner text is empty. Click the name to open or fold the card.
  2. Run this action (switch), move up, move down, duplicate, remove, and open or fold.
  3. The { } button inserts a variable at the cursor. The preview line under the field shows the text with example values.
  4. The wait before this action runs. A folded card shows it as wait 3 s.
  5. Add action opens the list of actions below. The new card opens and the others fold.

Game hook changes a running single-player game, for example adding gil when someone redeems channel points. Pick the Game (Final Fantasy VII (2013)) and an Operation, then fill in its fields. Their { } menus add game variables such as {random_character} or {hooks.ff7.party.0.name}.

It needs Game Hooks turned on and the game running on Windows; battle-only operations are skipped outside battle. If an enabled Game hook action's hook is off or not attached, the whole connector is skipped, not only that action.

Supported games, operations and their extra variables are on Game Hooks.

Variables

A variable is a name in single braces, such as {username}. Mycelian replaces it with the event's value when the action runs. You rarely need to type one:

  • { } button: every field that accepts variables has one. It opens a searchable list, grouped (Event, Connector, Time, Message helpers…) with an example value for each. Click a variable to insert it at the cursor.
  • Variables panel: the list on the right of the editor. Click a variable to insert it where your cursor last was. If no field has been clicked yet, the variable is copied instead and Mycelian says Click into a text field to insert variables there. The panel is hidden when the window is narrow.
  • Dates and times: date and time variables show format… in the list, or a {{icon:tune}} button in the panel. Pick a ready-made format, or type your own under Custom. The variable is inserted as {time:%-I:%M %p}.

Date format codes

%H hour · %-I hour (12h) · %M minute · %S second · %p AM/PM · %A weekday · %a Mon · %B month · %b Jan · %-d day · %Y year. The - drops the leading zero (7:30, not 07:30) on Windows and macOS alike.

  • Names must match exactly. A name Mycelian doesn't know is left as written, braces and all, so a typo like {UserName} shows up in chat as {UserName}. The preview line shows this before you save. A known variable with no value, such as an empty cheer message, becomes empty text.
  • JSON fields (Event data, Headers, Body) take variables directly: {"user": "{username}", "amount": {amount}}. Inside quotes the value is made safe for JSON; without quotes a number stays a number. The editor checks the JSON with example values and shows Not valid JSON (…) if something is off.
  • Run a command quotes every variable it inserts, so chat text can't run extra commands.

Card labels

The connector card uses the same action names as the editor, with the most useful detail added, for example Send chat message → Twitch + YouTube, OBS — Set program scene, Play an alert: Raid, Show a banner (until replaced), Press keys / click: ctrl+b, Write to a file: events.txt or Web request → example.com. Search on the Connectors tab matches these labels.

Good practice

  • Build one action, test it with Save & test, then add the next.
  • Give overlays time: set a wait on an action that depends on a scene or banner from the previous one.
  • Keep chat replies short and rare. Add conditions or a Cooldown so a busy chat does not trigger a flood.
  • Keep viewer text away from Press keys / click, and only run commands you trust.
  • If actions cause lag, see Performance Optimization.
