A command is a word that starts with !. When someone types it in Twitch chat, the chatbot posts your reply. Replies can include variables such as the viewer's name, the words they typed after the command, or live Twitch info like how long they have followed.

{{icon:schedule}} About 3 minutes {{icon:place}} ChatbotCommands {{brand:twitch}} Needs a Twitch connection

The chatbot replies as your channel, or as a separate bot account if you set one up. Both are covered in Twitch Setup.

The Commands tab

  1. Search matches the name, description, command, aliases and reply. All / On / Off narrow the list and show how many are in each. {{icon:refresh}} reloads the list. New command opens the editor.
  2. The name, the command with its aliases, and the description. The switch turns the command on or off without deleting it; a command that is off ignores chat.
  3. The reply as it would look, filled in with sample values, and tags for what is set: Counter · 7, who can use it (Subscribers, VIPs, Mods only), a Twitch lookup, the cooldown, a use limit, and where the reply goes (Twitch, YouTube, Discord channels or Shows as banner).
  4. How many times it was used and how long ago. Then {{icon:restart_alt}} Reset the counter to 0 (counters only), {{icon:play_arrow}} Test with sample data, {{icon:edit}} Edit (double-clicking the name also edits) and {{icon:more_horiz}} with Duplicate and Delete….
  5. Check {usr} means a variable in the reply could not be filled, usually a typo. Here {usr} should be {username}; it would be posted exactly as written.

With no commands yet, the tab shows No commands yet and a Create a command button.

What viewers see

Create a command

Open the editor and name it

Click New command (or Create a command). Click Name this command at the top and type a name for the card. Add a short description (optional) shows under it. The On switch decides whether the command works once saved.

Type the command

In 1 When · Command, type the word after the !, for example discord. Add other words under Also answers to; press Enter, space or comma after each. Pick Who can use it, and set a Cooldown or Limit if you want one.

Add inputs and a lookup if you need them

2 With · Inputs names the words viewers type after the command. 3 Look up · Twitch info fetches live info such as follow age or uptime. Skip both for a plain reply.

Write the reply

In 4 Then · Reply, type what the bot says. The { } button inserts a variable, and the line under the text shows the reply with sample values. Choose where it goes with Send to.

Save and test

The bottom left says Ready to save, or names the first thing still missing. Click Create command, or Save & test to save and try it once with sample data. Nothing is posted by a test.

The command editor

  1. The command (no spaces; the ! and capitals are dropped for you), its aliases, who can use it, the cooldown, the use limit and the type. See the next two sections.
  2. Each input gives a word a name. Here the first word becomes {target}; if the viewer types nothing after the command, {target} is {username}. The Viewers type line shows the result.
  3. An optional Twitch lookup. Its Gives you chips are the variables it adds, and the last row is the text posted instead when it fails. See Twitch lookups below.
  4. The reply, with a live preview using sample values. Send to picks Twitch and/or YouTube, Channel adds Discord channels, and Show as banner shows the reply on the chat overlay banner instead of posting it.
  5. Variables lists everything this command can use, with example values. Click one to insert it where your cursor was; {{icon:tune}} picks a date format. New custom variable opens the builder (see Chatbot Variables). The panel is hidden when the window is narrow.
  6. The status names the first problem, such as Type the command viewers use., !dc is already used by “Discord link”. or Write the reply. Save & test saves, then tests with sample data.

Closing the editor with unsaved changes asks Close this command without saving? Your edits will be lost. Choose Keep editing or Discard. !quote and !add_quote are built in while quotes are on, so they can't be used as commands or aliases.

Who can use it, cooldown and limit

SettingWhat it does
EveryoneAnyone in chat.
SubscribersSubscribers (and founders), plus VIPs and mods.
VIPsVIPs and mods.
ModsModerators only. The card says Mods only.
Cooldown secAfter the command runs, it is ignored for this many seconds. One cooldown per command, shared by everyone. 0 means none.
Limit usesTotal uses allowed; after that the command stops answering. 0 means no limit. Once it has been used, the editor shows used 12 · reset; click it to start the count over.

You, the broadcaster, can always use your own commands. Chat badges decide everyone else's level. When a command is blocked (not allowed, on cooldown or out of uses) the bot stays silent; nothing is posted in chat.

Command types

Posts the reply. The card shows how many times it was used.

Command: !discord
Reply:   Join us on Discord: https://discord.gg/example

Adds one every time it is used, and {count} is the new total. Count now sets the number by hand. Keep the count after a restart is on by default; turn it off to start from 0 each time Mycelian starts. {{icon:restart_alt}} on the card asks Reset command counter? and sets it back to 0.

Command: !deaths      Type: Counter
Reply:   Deaths this stream: {count}

Sets a counter command back to 0. Pick it under Resets, which lists your counters (for example !deaths · Death counter). {target_command} is the counter's command and {target_count} its value before the reset. The reply is optional: leave it empty to reset silently.

Command: !resetdeaths   Type: Reset a counter   Resets: !deaths
Reply:   Reset !{target_command} (was {target_count})

Set Who can use it to Mods so viewers can't clear it.

Inputs

Viewers can type words after a command, like !hug @friend. You can always use them as {command_word_1}, {command_word_2}… or {command_message} for everything after the command. Inputs give them friendlier names:

  • Add input adds a row: pick Word 1 to Word 9, then type a name such as target (lowercase letters, digits and _). Use it in the reply as {target}.
  • The third box is If empty: what to use when the viewer typed fewer words. Leave it blank for empty text, or use variables, for example {username}.
  • Inputs can feed a lookup: Check can be {target} instead of the person who typed the command.

Twitch lookups

Click Look up Twitch info in step 3 to fetch live info for the reply, or to have Twitch do something (change the title, raid, shout out). Lookups use the Twitch account you connected in Twitch Setup: ids, tokens and headers are filled in for you.

Every lookup also gives {lookup_error}, the reason it failed, for the fallback text. Viewer and channel lookups have a Check or Channel box: Whoever typed the command, one of your inputs, or A name I type… (a name or a variable such as {command_word_1}; @ and twitch.tv links are cleaned up). When you pick an input and the viewer leaves it out, the lookup checks whoever typed the command instead.

When a lookup fails

  • It worked: the reply is posted.
  • It failed and the fallback box has text (If it fails, or If they don't follow for follow age): the fallback text is posted instead.
  • Follow age, not following, empty fallback: the normal reply is posted, with {followage} = not following and {is_following} = no.
  • Any other failure with an empty fallback (name not found, Twitch not connected, no permission, no answer within 20 seconds): nothing is posted.

A failed lookup still counts as a use: the cooldown starts, the limit goes down and a counter goes up.

Advanced: any Twitch API request

Use any Twitch API request (advanced) calls any Twitch Helix endpoint. Pick the method (GET, POST, PUT, PATCH, DELETE), type the path after helix (for example /channels/followers), and add parameters with + Add parameter. Other methods also get a body box for JSON. Values can use any variable plus {broadcaster_id}, {chatter_id} and {chatter_login}; broadcaster_id and moderator_id are filled in when you leave them out. The result gives you {api_field} from the first result (for example {api_followed_at}), {api_total}, {api_count} and {api_status}. A status outside 200–299 counts as a failure. Commands made with the old API Integration section were moved here automatically.

Testing a command

{{icon:play_arrow}} Test on a card, or Save & test in the editor, runs the command once on a copy, as if you typed !followage hello world example. Lookups use example values. Nothing is posted, and uses, counters and cooldowns don't change. The result appears as a message, for example Test reply: TestViewer has followed for 2 years, 3 months!, or Didn't run: Command is disabled.

Questions

Nothing happens when I type the command

Check that the card is on, the message starts with ! and the command has no typo, and that Twitch is connected. Commands only listen to Twitch chat; YouTube chat does not trigger them, even when YouTube is in Send to. A blocked command is silent too: check Who can use it, the cooldown and the limit, and whether a lookup failed with an empty fallback.

A variable shows up as plain text like {usr}

A name the chatbot doesn't know is posted exactly as written. The card warns with Check {usr}, and the editor says Not a variable here, so it is posted as written, often with a suggestion such as did you mean {username}? Some variables only exist for one type: {count} on counters, {target_count} on reset commands.

My reply is very long

Twitch allows 500 characters per message. The editor warns when the preview is longer, and the bot splits it at word breaks into up to 3 messages; anything beyond that is cut off and ends with ….

Can a command repeat on a timer?

Use a Timer event instead. Older commands that repeated on a timer were turned into Timer events automatically. See Chatbot Events.
